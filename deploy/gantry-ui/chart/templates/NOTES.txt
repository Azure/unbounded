The dashboard listens only on the Linux system node's loopback interface.
No Service or Ingress is installed. Open a trusted local tunnel:

  kubectl --namespace {{ .Release.Namespace }} port-forward --address 127.0.0.1 deployment/{{ include "gantry-ui.fullname" . }} 8088:8088

Then open http://127.0.0.1:8088.

Dashboard workload identity subject:
  system:serviceaccount:{{ .Release.Namespace }}:{{ include "gantry-ui.fullname" . }}
{{- if .Values.builder.enabled }}
Builder workload identity subject:
  system:serviceaccount:{{ .Release.Namespace }}:{{ include "gantry-ui.fullname" . }}-builder
{{- end }}

Configure these federated identity subjects before accessing ACR. The cluster must
have the Azure workload identity webhook and an existing Gantry namespace.
Only one loopback dashboard can bind port 8088 per node; pin additional releases
to different nodes with nodeSelector.
